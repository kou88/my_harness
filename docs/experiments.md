# 仮説検証

「記事」の左にある「テーマ」タブから開く。AIタブの設定メニューからの入口はテーマタブへ移した。

タブ順は「今日・本・テーマ・記事・AI・テレビ」。iPhoneでは標準タブバーの上限によりAIとテレビを「More」から開く。AIのサイドバーからもテーマへ切り替えられる。

最初にテーマ一覧を表示する。テーマを開くと上部の「仮説・検証TODO・結果ノート」の3タブで、そのテーマに属する内容を切り替える。テーマの目的・対象・前提は右上の情報ボタンから開く。検証TODOは仮説ごと、結果ノートは検証TODOごとに並べ、アーカイブした親に属する項目は一覧に表示しない。結果ノートは件数を5件に制限せず表示する。

テーマ一覧の右上の「＋」からテーマを追加する。テーマ名は必須。ステータスは進行中で開始し、保留・終了も選べる。目的・対象・前提も入力でき、保存後は作成したテーマを開く。通信エラーで保存結果が分からない場合は入力を保持して固定し、同じoperationIdと内容で再試行する。保存中の多重送信を防ぎ、認証セッションが変わった場合は作成結果を別セッションに表示しない。

テーマ詳細の各タブにも右上の「＋」を設ける。仮説は現在のテーマへ追加し、検証TODOは仮説、結果ノートは検証TODOを一覧から選択する。選択肢は同じテーマのアーカイブされていない親に限定する。親がない場合は先にその追加画面へ進める。保存後は開いているタブの一覧とテーマ一覧の件数を更新する。新しいTODOの実施者はログイン中の本人とし、人間／AIへの割当変更はCLIで行う。仮説は未検証・検証中、TODOは未着手・進行中・保留から開始し、追加操作で完了や判定を行わない。ノートでは観測日時・事実・解釈・参照元を分けて入力でき、Markdownを保持する。

画面の補助説明は増やさず、階層、状態、TODO完了数、日付で関係を示す。ノートでは事実と解釈を分け、参照URLを開ける。訂正履歴、判定時の仮説、当時の根拠ノートを確認できる。Pull to refreshとテーマ一覧の50件単位の追加取得を使う。既存データの編集・判定と、テーマ横断の期限別取得はCLIから行う。

ExperimentAPIClientは既存の認証・bootstrap・通信処理を利用する。独立した端末DBは作らない。ログアウト時に一覧・詳細を消去し、進行中リクエストの応答が別セッションへ混入しないよう所有者と世代を照合する。

受け入れ確認用JSONは、ローカルAPIへ実CLIで登録・訂正・完了・判定して取得した表示用フィクスチャ。API契約テストで4階層、TODO進捗と仮説判定の独立、必須基準の欠落、期限なし・未完了を確認する。表示用データは本番へ登録しない。

ビルド・画面確認：MyHarness.xcworkspace / MyHarness / Debug、iPhone 17 Pro（iOS 26.4、AD933F96-24D3-4D6C-A728-8FA3E1DEBD2C）。この追加画面の確認時はXcodeBuildMCPが利用できず、xcodebuild・simctlとComputer Useを使用する。App Group用の再署名はSimulator成果物だけに行い、配布署名は変更しない。
