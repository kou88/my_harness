# AIチャット v4

2026-08-30。旧AI画面・APIクライアント・状態管理・ドメインを置き換え、my_apiの `/api/v4/ai` へ接続する。TVなど他機能と既存のCognitoログインを維持する。

- 実行PCから公開されたモデル名を選択する。初回のモデル自動選択や外部プロバイダへの自動切替はしない。
- コンテキスト長、出力上限、reasoning effortをモデルごとに保存する。モデルの能力と推論用トークン予算を確認してから送信する。
- 回答はストリーミング表示。実行詳細で思考、ツール入力/結果、コード実行、使用量を開閉する。
- 会話・実行・イベントはAPIが保持。画面を閉じても実行を止めず、前景復帰後に保存済み連番から追いつく。
- 送信結果不明時は同じ実行UUIDで再送する。停止ボタンだけが明示的に中断を要求する。
- 会話の削除はAPI履歴の削除。PC上の生成ファイルやHermesの長期メモリは削除しない。

旧v3 AI経路には接続しない。v4未配備、PCオフライン、設定不足はエラーを表示する。旧AI履歴を取り込む互換コードは追加しない。

検証: Swiftドメインテスト、Release Simulatorビルド。ログイン後の状態をObservableへ反映し、未ログイン時の認証エラーも表示する。出力上限は数値を直接入力できる。実機バックエンド確認はprivate運用repo cmp170hx_ubuntuへ記録する。認証情報は本repoに含めない。

実行詳細は保存済みの生データを変更せず、execute_codeのPythonコードとResponsesのinput_textに包まれた結果を表示時に整形する。プレーンテキストのツール結果はそのまま表示する。

## 狭幅チャットUI

Open WebUI v0.11.1の実画面（幅393 CSS px）を参照し、2026-08-30にAIタブを再構成した。

- AI画面はアプリのライト／ダーク設定に追従。新規画面は中央のモデル名と2行構成の入力欄、会話中は下端に同じ入力欄を固定する。
- 通常のNavigationBar・TabBarはAI画面だけ隠し、左上から履歴・検索のドロワーを開く。MyHarnessの他機能にはドロワー下部のメニューから戻れる。
- モデル選択は検索付きの一覧。完全なモデル名とオンライン状態を表示する。推論量・トークン上限は右上の設定から変更する。
- ユーザー文は右寄せの丸い吹き出し。回答はカードで囲まず、思考とツールを回答の前で個別に開閉する。コードの入力と結果にコピー操作を付ける。
- 送信は配色に追従する丸ボタン、実行中は停止へ切替。キーボードとsafe areaを考慮し、画面の移動では実行を停止しない。
- Open WebUIのブランド名はMyHarnessに置換。音声対話・添付・一時チャット・再生成はv4契約にないため、動かない模倣ボタンは置かない。「もっと見る」からコード/Web調査の文面を入力できるが、送信するまで実行しない。

接続先・永続化・認証は同じv4契約を利用し、Open WebUIへのWebView埋め込みや履歴同期は行わない。iOS 17以上で動作するSwiftUI実装。

検証: Swift 38テスト、iOS 17 deployment targetでのRelease Simulatorビルド成功。iPhone 17 Pro / iOS 26.4で新規画面、履歴ドロワー、7モデルの一覧、会話読み込み、思考・コードの開閉、新UIからの追加送信とロード進捗を確認。遷移元のonDisappearで遷移先の読み込みを中断しないよう、購読の切替は状態管理側に集約した。

## チャット内の操作

- 配色はアプリ共通。AI画面・設定シートのダーク固定を撤去し、入力欄・ドロワー・コード・送信ボタンも同時に切り替わる。
- 入力欄のbrainアイコンからreasoning effortを直接選択する。推論budgetに対して出力上限が足りない選択肢は、変更後の出力上限をメニューに明示して同時保存する。実行中・送信確認待ちには変更しない。
- 回答・ユーザー文・思考・コードは選択可能なネイティブテキストで表示し、任意の範囲をコピーできる。回答のMarkdownは1つの選択領域にして、段落をまたいで選択できる。全文コピーも維持する。
- 履歴の各行のメニューと会話ヘッダーから削除できる。確認ダイアログを出し、実行中の会話は削除しない。別の会話を削除しても現在の会話・購読は維持する。
- 画面左端32ptから右へスワイプして一覧を開く。一覧は左スワイプで閉じる。中央のテキスト選択やコードの横スクロールと分離する。

## 複数チャットと切り替え

AIタブはNavigationStackへ会話画面を積まず、1つの画面の表示先を切り替える。会話ごとに下書き・モデル設定・送信確認・ストリームを保持し、遅れて返ったHTTP応答は元の会話だけに反映する。新規チャットへの切り替えも、他の会話の送信・実行が終わるまで待たない。

複数の会話へ依頼できるが、現在のOS AgentのGPU実行はキューによる順次処理。履歴には「送信中」「実行中」「待機中」を表示し、待機側でも停止を要求できる。同じ会話への重複実行は引き続き許可しない。別会話の削除・名前変更・前景復帰の読み込みで表示先を変えない。

検証（2026-08-30）: `bash scripts/test-ai-chat-state.sh` は実際の状態管理を制御可能な通信テストダブルと組み合わせ、下書き保存、GET/送信の応答順逆転、受理済みrunの巻き戻り防止、2会話のストリーム分離、停止対象、別会話削除を確認する。外部通信・GPU・本物の認証情報を使わず、実行は20秒で打ち切る。iOS Build CIにも追加した。

Release Simulator / iPhone 17 Pro（iOS 26.4）で、ライト↔ダークの即時追従、入力欄からの推論量変更、単語だけの選択コピー、左右スワイプ、空の検証用会話の確認付き削除を確認。実際のUIから別々の依頼を送り、A実行中・B待機中を一覧と会話内で確認し、Aには4、Bには5が返って両方完了した。既存のユーザー会話は削除していない。
